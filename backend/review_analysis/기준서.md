
## 1. 목적·설계 원칙

1. **정보태그 단일 레이어.** 긍정/부정을 따로 칸으로 두지 않는다. 검색은 "느낌"이 아니라 "속성"으로 매칭하므로 정보태그 하나로 통합한다.
2. **속성을 두 유형으로 구분해 극성 처리** (아래 2장).
3. **별점 미사용.** 어떤 판정·부여에도 별점을 쓰지 않는다.
4. **상세페이지 파싱 담당 축 제외.** 소재 조성·색상 옵션·가격은 다른 담당(파싱) 몫 → 리뷰 태깅 범위 밖.
5. **태그는 문장이 아니라 짧은 정규화 키워드.** ("오버핏이 너무 이뻐요" → `오버핏`)
6. **지도 원칙**: 상세페이지가 이미 말해주는 건 열로 만들지 말고, **리뷰에서만 알 수 있는 것**을 태그로 만든다(실제 핏·두께·품질·용도).

## 2. 태그 체계 (취향형 / 품질형)

- **취향형(중립)** — 두께·무게·핏방향·색조·계절·용도. **태그는 사실(방향)만** 저장하고, 좋고 나쁨은 **손님 검색어가 결정**. 예: `도톰함`은 겨울 검색엔 +, 여름 검색엔 −.
- **품질형(방향 내장)** — 비침·봉제·프린팅·물빠짐·수축·넥늘어남·보풀·색정확도. **좋음/나쁨 상태를 태그 값에** 담는다(`비침없음` vs `비침있음`).

전체 태그 목록·유형·동의어(alias)는 [`정보태그_사전.md`](정보태그_사전.md) 참조 (L1 속성 / L2 정보태그 / L3 alias 3층 구조).

**코드 어휘 정합**: 핏(오버·레귤러·슬림)·기능성(냉감·통풍·신축·흡습속건)은 `client/features/catalog/domain/tee.ts` 표준값으로 정규화(검색 파싱과 일치).

## 3. 감성 판정 3단 파이프라인 (개정판)

- **1단 — LLM 전수 정독 (주력)**: 모든 분석 대상 리뷰를 문장 단위로 정독 → 속성·긍부정·사유·오타해석. **출력은 사전 L2 태그 닫힌 집합으로 고정**(자유서술 금지). 규칙: 양보 어미 뒤 부정도 해당 속성 부정, 별점 미사용, 배송·CS 무시, **추측·기대 표현("~것 같다") 판정 안 함**.
- **2단 — 기계 교차 검증**: 중심은 **Kiwi 형태소+키워드 사전 커버리지 체크**(속성 놓침 감시) + **LLM 자기일관성**(다중 판정 다수결). KoELECTRA-NSMC 감성모델은 **거친 전체극성 트립와이어로만**(영화평 도메인·문서단위라 속성 대조기로 부적합).
- **3단 — 불일치 재판정**: 1·2단 불일치 + 위험신호(R1 하자문장 / R2 무속성 장문 / R3 미등록·오타 / R4 모델 저확신) 리뷰를 **1단과 독립적으로**(다른 모델/다중샘플) 재판정. 재판정 내역 기록.

## 4. 제외 필터 (슬림)

분석 전 제거: ①무속성 리뷰 ②제품 무관(배송·CS만) ③중복 리뷰(사진 pHash·텍스트 복붙) ④협찬/체험단.
- "15자 미만" 길이 컷은 **삭제** — 기준은 길이가 아니라 "속성 유무"(짧아도 속성 있으면 유지).
- **리뷰타입(한달사용/재구매)은 안 씀** — 점수 산정용이라 무점수 시스템엔 불필요. 내구성 태그는 텍스트 자체가 실사용 증거 + 추측 배제 규칙으로 자족.

## 5. 저장 스키마

- 컬럼 `review_tags text[]` (products 테이블, GIN 인덱스) — **유니크 셋**(중복 태그 안 적음). 검색은 태그 유무만 보므로 건수 불필요.
- **건수 컬럼 안 만듦.** 건수는 극성 갈림 판정에만 순간 사용, 저장 안 함.
- **상태 3종(중요)**:

  | 값 | 뜻 |
  |---|---|
  | `NULL` | **미분석** (아직 안 봄) — 기본값(default 제거됨) |
  | `{unknown}` | **분석했으나 태그 0개** (명시적 sentinel) |
  | `{도톰함,…}` | 태그 있음 |

  - `[]`(빈 배열)은 **안 씀** — "진짜 없음"인지 "오류로 안 써짐"인지 구분이 안 되므로 `{unknown}`로 명시.
  - 자동화는 `WHERE review_tags IS NULL`로 **미분석만** 골라 처리.
  - `unknown`은 **예약어**: 검색(`@> {도톰함}`)엔 안 걸리고, 상품카드 표시 시 태그 목록에서 필터(진짜 태그 아님).

## 6. 부여 규칙

- **부여 최소 임계값 없음 — `1건이라도 언급되면 붙임`(확정)** — 최소 건수 임계값을 두지 않는다. 태그가 1건이라도 있으면 부여. 건수는 오직 아래 **극성 갈림(상반 태그가 있을 때)** 판정에만 쓴다.
- **변별력 낮은 태그도 삭제하지 않음** — `재질좋음`처럼 흔한 태그도 그걸 검색하는 손님이 있으므로 유지(흔함은 랭킹에서 다룰 문제). 목표는 정확한 검색이지 태그 솎아내기가 아님.
- **극성 갈림 처리 규칙(확정·3지선다)** — 한 속성 그룹에 상반 태그가 달릴 때:
  1. 값별 언급 수를 센다 — **최근 1년 리뷰 ×2 가중**
  2. 한 값이 그룹 (가중)언급의 **2/3 이상** → 그 값 채택, 나머지 드롭
  3. 2/3 미만(비등) → **그룹 전부 드롭**
  4. **중립값도 투표에 포함(3지선다)**: 두께[얇음/두께적당/도톰함], 핏크기[작게나옴/정사이즈/크게나옴], 기장[기장짧음/기장적당/기장김]. 예: 정사이즈6 vs 크게2 → 정사이즈 / 2:2 → 둘 다 드롭. (정사이즈·두께적당을 "중립이라 제외"하지 않음)
  5. 2지선다(중립 없음): 무게·비침·수축·건조기·넥·프린팅·물빠짐·봉제·색정확도·구김·신축·보풀·핏스타일(오버핏/슬림핏)
  - 최근 가중이 원단 교체(옛날↔최근 갈림)를 자동 처리. 구현 원칙: **LLM은 리뷰별 분류만, 건수·가중·2/3 계산은 코드**.

## 7. 색 처리 — 라우팅 폐기 (팀 결정 2026-07-23)

- **리뷰 태깅은 색을 다루지 않는다.** 팀 회의 결정으로 색 종속 라우팅(옵션태그·구매색 읽기·색밴드)을 **전면 폐기**. `비침있음`·`물빠짐`도 **다른 태그처럼 상품에 그냥 붙이는 평범한 정보태그**로 처리한다(색 구분 없음).
- **트레이드오프(수용됨)**: 흰색만 비치는 상품에도 `비침있음`이 상품 전체에 붙어, 검정 검색자에게 약한 과잉경고 가능. 단 비침은 대개 밝은색 이슈라 실무 영향 작음 → MVP는 단순성 우선.
- 상품 색(검색 필터용 `base_color`)은 파싱 담당(별도)의 몫이며 이 결정과 무관. 리뷰는 색을 안 건드린다.
- tee.ts 색 팔레트 확장(11→22색)은 검색 정확도용 **별도 팀 논의**(리뷰 태깅과 분리). 22색 후보안은 리서치로 보유.
