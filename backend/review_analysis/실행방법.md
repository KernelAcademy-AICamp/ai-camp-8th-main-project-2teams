# 리뷰 태그 분석 실행 방법 (런북)

새 세션·팀원 누구나 이 문서대로 하면 리뷰 → 정보태그 → DB 저장까지 재현 가능.
규칙 상세는 [`기준서.md`](기준서.md), 태그 어휘는 [`정보태그_사전.md`](정보태그_사전.md), 1단 지시서는 [`1단_추출_프롬프트.md`](1단_추출_프롬프트.md).

## 새 세션에서 시키는 법 (한 줄)

> **"`backend/review_analysis/실행방법.md`대로 리뷰 태그 분석 돌려줘. 대상 = <상품/리뷰 지정>. DB 저장은 <할지/말지>."**

메모리에 설계 결정이 자동 로드되고, 이 폴더 문서에 방법이 다 있음.

## 파이프라인 (4단계)

### 0. 대상 정하기
- 어떤 상품의 리뷰를 분석할지 정함. 리뷰는 `/Users/fkwlsdn/dev/team_pj/data/reviews/reviews_*.json`.
- ⚠️ **주의**: 현재 `data/reviews/`는 **일반 반팔티**용이고 Supabase `products`(클라이밍 티)와 **매칭 안 됨**. DB 상품에 실제로 태그를 쓰려면 **그 상품들 리뷰를 먼저 수집**해야 함.

### 1. 1단 LLM 추출 (리뷰별 + reviewId)
- 상품별로 리뷰를 읽어 [`1단_추출_프롬프트.md`](1단_추출_프롬프트.md) 규칙으로 태그 분류.
- **LLM 방식**: NVIDIA qwen 키(`client/.env.example`의 `NVIDIA_API_KEY`)는 현재 403(무효). → **Claude 에이전트 병렬**로 돌림(상품 5~6개씩 나눠). 리뷰가 많으면 상품당 캡(예 30) 두되 log로 남김.
- 출력(상품별): `{"index":n,"product":str,"hits":{"<reviewId>":["<태그>",...], ...}}` 를 모아 `agents_out.json`.
- 규칙 요지: 허용 태그만 / 추측·총평 제외 / 양보어미 뒤 부정 포함 / 배송·별점 무시 / 색은 안 읽음(비침·물빠짐도 그냥 태그).

### 2. 부여 (극성 갈림) — 코드
```
python3 부여_resolve.py agents_out.json [리뷰폴더]
# 리뷰폴더 생략 시 기본값 사용. 날짜 못 찾은 리뷰는 '최근가중만' 스킵(×1)하고 태그는 그대로 셈.
```
- **최소 임계값 없음**: 1건이라도 언급된 태그는 붙인다.
- **극성 갈림(상반 태그가 있을 때만)**: 3지선다(두께·핏크기·기장, 중립 포함) + 2지선다(비침·수축·프린팅 등). 최근 1년 ×2 가중, 한 값 2/3↑이면 채택·아니면 그룹 드롭.
- 결과 → `final_resolved.json` (상품별 최종 `review_tags`).

### 3. DB 저장 (REST, 브라우저·CLI 불필요)
- `backend/.env.local`의 `SUPABASE_URL`+`SUPABASE_SECRET_KEY`로 `products.review_tags` UPDATE(PATCH).
- 매칭 키: 리뷰의 상품 ↔ `products.source_product_id`. (지금 데이터는 매칭 0 — 0단계 주의 참고)
- DDL(열 추가)은 REST로 불가 → 이미 `review_tags text[]` 컬럼 생성돼 있음.

## 확정 규칙 요약 (기준서 §6)
- 정보태그 = 유니크 셋(text[]), 별점 미사용, 색 라우팅 폐기.
- 부여 최소 임계값 = **없음(1건도 부여)**. 건수는 극성 갈림에만.
- 극성 갈림(상반 시만) = **3지선다/2지선다 2/3 규칙**(중립값도 투표 포함).
- 변별력 낮은 태그(재질좋음 등)도 **삭제 안 함**.
- LLM은 분류만, 건수·가중·2/3 계산은 코드.
