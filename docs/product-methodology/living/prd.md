## 1. 배경

러닝·라이딩·클라이밍·크로스핏처럼 **운동 중 남에게 보이는 게 등판인 사람들**에게, 티셔츠의 정면은 사실상 등판이다. 그래서 이들은 **등판 그래픽 티**를 원한다(관찰된 원사례: 노란 클라이밍화에 맞출 백프린팅 티). 그런데 쇼핑몰은 등판을 대표컷으로 쓰지 않아 **등을 보려면 상품마다 상세페이지를 열어야 하고**, 등판 그래픽 색은 상품 대표색에도 안 잡힌다. 무신사에는 상품도, 44색 공식 색 필터도 다 있지만 — 색 필터는 **상품 대표색 1개** 기준이라 "바탕 흰 + 백프린팅만 노란" 같은 **조합**을 표현할 축이 없고, 검색도 키워드 매칭이라 조합 질의를 해석하지 못한다. 결과는 대표 썸네일뿐이라 등판·소재·사이즈를 상품마다 상세페이지로 확인해야 한다. → **팀 내 클라이머가 4시간 탐색 후 실패**(직접관찰, 네이버·무신사). 근본 원인은 속성 구조화의 **축이 사용자의 탐색 언어와 어긋난 것** — 그래서 우리는 무신사 위에 '발견 레이어'를 얹는다(→ [problem-validation 5Why 재정립](../foundation/problem-validation.md)). Loop1 표본인 클라이밍은 인구 ~50만·성장세에 암장 굿즈 티 문화·기능성 담론이 확립돼 있고, 크로스핏(박스 티)이 구조적으로 같은 짝이다(세그먼트 전체 모수는 미조사 플래그). 데이터 소스 = 무신사(D14), 첫 타겟 = "등이 보이는 운동"(D15), 수집 범위 = 포트폴리오 범위(D16) — 사유는 [iterate-log](iterate-log.md) 중간 의사결정.

## 2. 목표 (SMART)

- 6주 안에 **3×2주 린 루프**로 MVP를 배포하고, **각 루프 종료 시 Amplitude 데이터+인터뷰 기반 의사결정 1건**을 문서화한다([iterate-log](iterate-log.md)).
- **Loop 1 종료 시**: 배포 URL 확보 + 속성 추출 정확도 베이스라인 + 검색 성공률 베이스라인 측정.
- **프로젝트 핵심 성과 = "데이터로 의사결정하는 과정"을 3루프로 입증.**

## 3. 성공 지표 → 상세 [metrics.md](metrics.md)

- **북극성**: 검색 세션당 "구매 진입(상품 페이지 이동 · outbound 클릭)" 비율 / 구매 진입까지 시간
- **선행**: 검색 성공률·CTR·상세 도달률·**구매 진입 클릭률**·구매의향·탐색시간
- **가드레일**: no-result율·오검색 체감
- 부트캠프 규정: GMV·구매CVR·Add-to-Cart 직접개선 주장 금지 → 선행지표로 검증

## 4. 페르소나 → [customer-profile.md](customer-profile.md)

**등이 보이는 운동을 하는 20~30대.** 세그먼트를 정의하는 건 종목이 아니라 **"운동 중 남이 내 등을 본다"는 조건** — 그래서 등판 그래픽에 돈과 시간을 쓴다. **Loop1 표본 = 클라이밍·크로스핏**(모집 가능), 확장 후보 = 러닝·라이딩·스케이트/서핑(축엔 맞으나 Loop1 미검증). (첫 타겟=beachhead)

## 5-1. 사용자 시나리오

> 성공 = 관찰 가능한 한 행동(구매 진입 클릭).

1. 노란 클라이밍화를 새로 산 사용자가 검색창에 **"흰 바탕에 노란 백프린팅, 오버핏"** 입력
2. 결과 카드에서 **등판 컷 + 바탕/프린팅 색칩 + 핵심속성**(핏·소재·사이즈유무)으로 한눈에 비교
3. 마음에 드는 티의 **무신사 상품 페이지로 이동** = 구매 진입(성공 행동, Amplitude 기록)

실패 흐름: 결과 0건 → no-result 이벤트(가드레일 지표) + 조건 완화 제안.

## 6. 요구사항

### P0 (Loop 1)

- **카탈로그**: 무신사 프린팅 반팔티 50~100개 큐레이션(수집·적재는 백엔드 Supabase 활용, D14)
- **속성 추출**: 상품 이미지 → **비전 LLM 단일 호출 → JSON**. 스키마 아래 §7.
- **검증 루프**: 자동추출 → 사람 샘플 검증(속성별 정확도) → 임계 미달 속성은 검색 노출 제외/플래그
- **자연어 검색**: 쿼리 → LLM 파싱(속성화) → 속성 필터·랭킹
- **결과 카드**: 등판 이미지 · 추출 색칩(바탕/프린팅) · 핵심속성(핏·소재·사이즈유무) 미리 노출
- **상품 페이지 이동(구매 진입, outbound) 링크** + **Amplitude 계측**(§metrics 이벤트) + Vercel 배포

### P1 (Loop 2~3)

- 카탈로그 확장(200~500) · 추출 정밀화(색 분리 OpenCV 보조/OCR) · 신발색 매칭 훅 · 필터 고도화

### P2 (v2+)

- 리뷰 본격 · 비주얼 유사검색 · 대화형 재질문 · **확장 종목**(러닝·라이딩·스케이트/서핑 — 축엔 맞으나 Loop1 미검증) · 장비색 매칭 훅

## 7. 데이터·기술

- **속성 스키마**: 바탕색 / 프린팅색 / 프린팅위치(앞·뒤·전체) / 그래픽유형(레터링·캐릭터·로고·패턴) / 핏(오버·레귤러·슬림) / 소재·기능성(면·폴리·기능성; 추정 플래그) / 사이즈(유무·프리) / 가격 / 몰링크·이미지
- **아키텍처(안)**: 무신사 상품 수집(백엔드) → 이미지 비전LLM 추출 → 속성 DB(Supabase) → 검색(쿼리 LLM 파싱→속성 랭킹) → 프론트(Next.js + shadcn) → Vercel 배포 → Amplitude 로그
- **색 기준**: 바탕색·프린팅색은 **무신사 44색 공식 팔레트**에 매핑 — 태깅 기준표·필터·검증이 같은 축을 씀
- **데이터 제약**(→ [data-feasibility §6](../foundation/data-feasibility.md)): 무신사 공개 API 없음 — 수집은 사이트에 공개된 상품정보를 소량·저빈도로(D16, 포트폴리오 범위). 소재(상품정보 고시) 필드 일관성 미실측 → 소재는 추정 플래그 유지, 리뷰는 소규모 샘플 실험만.

## 7-1. 디자인 고려사항

- 결과 카드는 **등판 컷 우선**(대표컷 아님) — 상세페이지 확인 비용이 문제의 핵심이므로
- 바탕색/프린팅색 **색칩 분리 표기** — 조합 검색의 가치를 눈으로 증명
- **구매 진입 링크는 카드에서 가장 분명한 자리에** — 성공 행동을 정하지 않으면 모든 요소가 같은 무게가 된다
- 필터·정렬 문법은 **무신사 UI를 표준 멘탈모델**로 따름 — 익숙한 것을 새로 발명하면 장벽

## 11. 릴리즈·실험 계획

Loop 1(W1-2) 가치검증+최소추출 → Loop 2(W3-4) 데이터가 가리키는 곳 투자 → Loop 3(W5-6) 정밀화·확장·마감. 매 루프 Amplitude+인터뷰 → 의사결정([iterate-log](iterate-log.md)). 최종 산출물: PRD·배포URL·랜딩·인터뷰·인사이트 보고서·발표자료.

## 12. 팀 역할

4명 — **개발**(파이프라인·검색·앱·배포) · **카탈로그**(수집 기준·라벨 기준) · **시각속성 검증**(색·프린팅·그래픽) · **감각속성·인터뷰**(소재·기능성 태그, 사용자 인터뷰).
> 캐파는 **코드 1인 + 사람 검증 3인**으로 본다(→ [data-feasibility §0](../foundation/data-feasibility.md)).
